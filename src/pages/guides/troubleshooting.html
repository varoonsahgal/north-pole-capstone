How to debug anything

  1. Read the whole error. The useful part is usually the last line, or the first line in red.
  2. Ask what changed. It worked five minutes ago. What did you do since?
  3. Find the logs. Every service keeps them. The table below says where.
  4. Change one thing, then test. If you change three things and it works, you have learned nothing.
  5. Write it in the captain's log. What you saw, what you guessed, what it really was.

🐳 Docker

toomanyrequests: You have reached your pull rate limit

Docker Hub limits downloads per IP address. Use Amazon's public copies of the same images in your FROM lines: public.ecr.aws/docker/library/node:22-alpine and public.ecr.aws/nginx/nginx:1.27-alpine.

Bind for 0.0.0.0:3000 failed: port is already allocated

An earlier container still holds the port. docker ps shows it. docker rm -f NAME removes it.

no basic auth credentials or denied on push

Docker is not signed in to ECR, or the sign-in expired (it lasts 12 hours). Run the aws ecr get-login-password | docker login … line again. Check the image name starts with the full registry address.

I changed the code but the container shows the old version

The code is copied into the image at build time. Rebuild, remove the old container, and run a new one. Check with docker ps that the container you are looking at is the new one.

no space left on device

docker system prune -af deletes unused images and build cache.

🧱 Terraform

Network Configuration must be provided when networkMode 'awsvpc' is specified

Your ECS service has no network_configuration block. Fargate tasks need to be told which subnets to use. See Mission 1, step 7.

… already exists (EntityAlreadyExists, ResourceAlreadyExistsException, BucketAlreadyOwnedByYou)

Something with that name exists and is not in your Terraform state. Usually it was made by hand, by a teammate from a different state file, or by another team using your prefix. Check the name and who made it. Delete the stray one, or use a different name.

No value for required variable, or Terraform asks me to type the team name

Terraform cannot find terraform.tfvars. It must be in the folder where you run the command, and contain team = "[[TEAM]]".

Error acquiring the state lock

A teammate is running Terraform right now, or a run crashed and left its lock behind. Ask the team. If nobody is running anything, terraform force-unlock LOCK_ID clears it (the ID is in the error).

Backend initialization required or Backend configuration changed

Run terraform init again, with the same -backend-config option as before.

terraform destroy hangs for many minutes on a security group or subnet

Something that Terraform does not know about is still using it. The usual cause is a load balancer created by Kubernetes. Delete the Kubernetes service first (kubectl delete service sleigh-list).

The plan wants to destroy and recreate something I did not touch

Stop and read which attribute is marked # forces replacement. Some settings, such as names, cannot be changed in place. If it surprises you, do not type yes. Ask.

🛷 ECS and the load balancer

The browser cannot connect to the load balancer at all

Either there is no listener on port 80, or the load balancer's security group does not allow port 80 from 0.0.0.0/0, or your browser changed the address to https://. Type http:// yourself.

503 Service Temporarily Unavailable

The listener works, but the target group has no registered targets. Is the service connected to the target group (the load_balancer block)? Are any tasks running at all?

504 Gateway Time-out, targets "unhealthy: Request timed out"

The load balancer cannot reach the tasks. The tasks' security group must allow port 3000 from the load balancer's security group. See Mission 1, step 8.

Targets "unhealthy: Health checks failed" (with or without a status code)

The load balancer reaches something, but not a healthy answer. Check the target group's port (3000), the health check path (/health) and the expected status code (200). If the details say "Request timed out" instead, it is the firewall: see the entry above.

Tasks stop with CannotPullContainerError

The task could not download the image. Three causes, most likely first: public IP is off (a task in a public subnet needs one to reach ECR); the image address or tag is wrong; or no image has been pushed yet.

Tasks stop with exec format error in the logs

The image was built for a different kind of processor. An image built on an Apple Silicon laptop is ARM. Your task definition says X86_64. Build in the workshop or in CodeBuild, which are both x86.

Tasks start, run for a minute, and are replaced, forever

They are failing health checks. The service kills unhealthy tasks and tries again. Look at the target group's health details and fix that. The tasks themselves are fine.

⚡ Lambda and API Gateway

AccessDenied … is not authorized to perform: s3:GetObject

The function's execution role may not read the object. Add a policy for s3:GetObject on arn:aws:s3:::your-bucket/wishlist.json. Check the bucket name in the code for typos too.

{"message": "Internal server error"} from the API, but the Lambda test passes

Use the method's Test tab in API Gateway and read the end of the log. The API guide's deliberate mistake lives here, so no more will be said.

{"message": "Missing Authentication Token"}

A misleading message. It means "there is nothing at this path". You forgot /gifts, mistyped the stage name, or did not deploy the API after adding the method.

{"message": "Forbidden"}

The stage does not exist at that address. Check the Invoke URL on the Stages page.

I changed the API and nothing changed

API changes only go live when you choose Deploy API. Lambda code changes only go live when you choose Deploy in the code editor. Two different buttons.

The browser console says blocked by CORS policy

The API's reply is missing the Access-Control-Allow-Origin header. With proxy integration, your function has to return it. See step 8 of the API guide.

Unable to import module 'lambda_function' or Handler … not found

The handler setting must be file_name.function_name. For a file named lambda_function.py containing def lambda_handler, that is lambda_function.lambda_handler.

🚚 Pipeline

The Source stage fails, or the connection is "Pending"

A connection has to be approved in the console by someone signed in to the GitHub account that owns the repository. Also check that the AWS Connector app was given access to this repository.

A push does not start the pipeline

Check the branch name in the Source stage. Is it main, and did you push to main? Did the push reach GitHub (look at the repository in a browser)?

Cannot connect to the Docker daemon

Turn on Privileged mode in the CodeBuild project's environment.

not authorized to perform: ecr:GetAuthorizationToken

Attach AmazonEC2ContainerRegistryPowerUser to the CodeBuild role.

Deploy fails: "did not contain a file named imagedefinitions.json" or "container name … not found"

The buildspec must write the file and list it under artifacts. The name inside it must equal the container name in the task definition.

The Deploy stage runs for ten minutes and then fails

The new tasks never became healthy, so ECS never finished the rollout. Debug it as an ECS problem: open the service and read why the new tasks stopped.

☸️ Kubernetes

You must be logged in to the server (Unauthorized)

The cluster does not know who you are. Whoever is running kubectl (your console user, or the CodeBuild role) needs an EKS access entry. See the EKS guide, steps 4 and 6.

Pods are ImagePullBackOff or ErrImagePull

The image address in the Deployment is wrong. It needs the full ECR address and a tag that exists. If it says IMAGE_PLACEHOLDER, you applied the file by hand without replacing the placeholder.

Pods stay Pending

kubectl describe pod will say why. Usually there are no nodes ready yet (kubectl get nodes), or the nodes are full.

The service's EXTERNAL-IP says <pending> for a long time

A minute or two is normal. After five, run kubectl describe service sleigh-list and read the Events.

The load balancer address exists but does not answer

New load balancers need a couple of minutes for DNS. If it still fails, check that the Service's selector matches the pod labels exactly, and that targetPort is 3000.

eksctl create cluster fails with a limit error

You probably ran it without --vpc-public-subnets, so it tried to build a new network. Delete the failed stacks with eksctl delete cluster --name $TEAM-eks and use the command from the EKS guide.
