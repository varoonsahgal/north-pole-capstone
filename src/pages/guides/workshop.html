Launch it

One person per team does this, once.

  1. Sign in to the AWS console. Check the region (top right) is United States (Oregon).
  2. Open CloudShell: the terminal icon (>_) in the top bar.
  3. Run the launch command with your team name: curl -fsSL https://varoonsahgal.github.io/north-pole-capstone/workshop/launch.sh | bash -s -- [[TEAM]]
  4. Wait about 8 minutes. It prints your workshop URL and password. Share both with your team, and with nobody else.
What is that command doing?

It downloads a small script that asks CloudFormation (AWS's own infrastructure-as-code service) to build a stack named [[TEAM]]-workshop. You can watch it in the CloudFormation console. Running the command a second time is safe: it just prints the URL and password again.

Use it

  1. Open the URL and enter the password.
  2. Open a terminal: ☰ menu → Terminal → New Terminal, or press Ctrl + `.
  3. Create and edit files from the file list on the left. Files save themselves after a moment.

See a web app that is running in the workshop

If something in the workshop listens on a port (for example a container started with -p 3000:3000), you can open it in your browser. Take your workshop address up to .cloudfront.net and add /proxy/3000/, including the final slash.

Working as a team

  • Everyone sees the same files and can open their own terminal.
  • It is not live co-editing. If two people edit one file, the last save wins. Agree who is typing.
  • In Mission 2, commit to git often. Git is how the two tracks share work safely.

If something goes wrong

We lost the URL or the password

Run the launch command again in CloudShell. It will not build anything new. It just prints them again. The password is also stored in Secrets Manager as [[TEAM]]-workshop-password.

The launch command failed

Read the last lines of the output. If it mentions a stack in ROLLBACK_COMPLETE, open CloudFormation, select [[TEAM]]-workshop, look at the Events tab for the first red line, then delete the stack and run the command again. If it says the region is wrong, switch the console to Oregon and open CloudShell again.

The page will not load, or the terminal keeps disconnecting

Check the address starts with https:// and ends in .cloudfront.net (plus the folder part). Some company networks block WebSockets. Try another browser, or disconnect from the VPN and try again. Tell your instructor if it persists.

Paste does not work in the terminal

The first time you paste, the browser asks for permission to read your clipboard. Choose Allow. You can also right-click and choose Paste, or use Ctrl + Shift + V.

"no space left on device"

Docker images pile up. Free the space with docker system prune -af and check with df -h /.

"docker: permission denied" or a tool is missing

Open a new terminal. If that does not help, the setup may not have finished. Ask your instructor to check /var/log/workshop-setup.log on the server.

Removing the workshop

Only when your instructor says both missions are over. From CloudShell:

aws cloudformation delete-stack --stack-name [[TEAM]]-workshop --region us-west-2

This deletes the server and every file on it. Anything not pushed to GitHub is gone. Destroy your Terraform resources first, because the state file for Mission 1 lives on this server. See the cleanup guide.
