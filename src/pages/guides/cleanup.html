Field guide · Both missions

Leave No Trace

Clusters and load balancers cost money every hour, whether or not anyone is using them. Cleaning up is part of the job.

{{hills}}

The golden rule

Remove things the same way you made them, and in the opposite order.

If you made it with…Remove it with…
Terraformterraform destroy, from the same folder, with the same state
kubectl applykubectl delete
eksctl create clustereksctl delete cluster
The console, by handThe console, by hand
The launch command (your workshop)Deleting its CloudFormation stack, last of all

Only ever delete things named [[TEAM]]-…. If you are not sure something is yours, ask before you delete it.

1

After Mission 1

cd ~/workshop/infra terraform destroy

Read the plan, type yes, and wait about three minutes. Keep your workshop. You need it for Mission 2.

2

After Mission 2

Work through these in order. Each step removes something that the next step depends on being gone.

a. Kubernetes first

The Kubernetes service created a load balancer that neither Terraform nor eksctl knows about. Let Kubernetes remove it, then delete the cluster (about ten minutes).

kubectl delete service sleigh-list kubectl delete deployment sleigh-list eksctl delete cluster --name $TEAM-eks --region us-west-2

b. Then Terraform

cd ~/workshop/YOUR-REPO/terraform terraform destroy

c. Then anything made by hand

If you built resources in the console (goals 2, 5 and 6) and never replaced them with Terraform, delete them in the console now. Work backwards: pipeline, build project, ECS service, load balancer, target group, task definition, cluster, API, function, bucket, and the IAM roles that were created for them.

d. Then the state bucket and the connection

ACCOUNT=$(aws sts get-caller-identity --query Account --output text) # The bucket has versioning on, so every old version must be deleted before the bucket can go aws s3api delete-objects --bucket $TEAM-tfstate-$ACCOUNT --delete "$(aws s3api list-object-versions \ --bucket $TEAM-tfstate-$ACCOUNT --query '{Objects: [Versions, DeleteMarkers][][].{Key: Key, VersionId: VersionId}}' --output json)" aws s3 rb s3://$TEAM-tfstate-$ACCOUNT

If you created the GitHub connection by hand, delete it under Developer Tools → Settings → Connections. On GitHub, you can remove the AWS Connector app under Settings → Applications.

3

Check for leftovers

This command only looks. It lists everything in the region whose name starts with your team name.

curl -fsSL https://varoonsahgal.github.io/north-pole-capstone/workshop/leftovers.sh | bash -s -- [[TEAM]]

Before the final step you should see only your workshop: the [[TEAM]]-workshop stack, its role and its security group. A few CloudWatch log groups may also be listed. AWS services create those by themselves. They cost almost nothing, and you can delete them in the CloudWatch console.

4

Last of all: the workshop

Wait for your instructor, and push first

Deleting the workshop deletes every file on it. Make sure your code is pushed to GitHub. Make sure steps 1 to 3 are finished, because the tools and the Mission 1 state file live on this server.

From CloudShell in the AWS console (not from the workshop itself):

aws cloudformation delete-stack --stack-name [[TEAM]]-workshop --region us-west-2 aws cloudformation wait stack-delete-complete --stack-name [[TEAM]]-workshop --region us-west-2 && echo "Workshop removed"

It takes about five minutes. Run the leftovers check once more. The goal is this line:

Nothing found. The North Pole is spotless.
