1

Write the buildspec

CodeBuild starts every build on a brand-new, empty machine. A file named buildspec.yml at the top of your repository tells it what to do. Create it in your workshop:

version: 0.2 # These three variables are set on the CodeBuild project (step 3): # AWS_ACCOUNT_ID, IMAGE_REPO_NAME, CONTAINER_NAME phases: pre_build: commands: - REGISTRY=$AWS_ACCOUNT_ID.dkr.ecr.$AWS_DEFAULT_REGION.amazonaws.com - REPO_URI=$REGISTRY/$IMAGE_REPO_NAME # Tag every image with the short git commit, so we always know what is running - IMAGE_TAG=$(echo $CODEBUILD_RESOLVED_SOURCE_VERSION | cut -c1-7) - echo "Logging in to ECR..." - aws ecr get-login-password | docker login --username AWS --password-stdin $REGISTRY build: commands: - echo "Building $REPO_URI:$IMAGE_TAG" - docker build --build-arg BUILD_ID=$IMAGE_TAG -t $REPO_URI:$IMAGE_TAG -t $REPO_URI:latest . post_build: commands: - docker push $REPO_URI:$IMAGE_TAG - docker push $REPO_URI:latest
PhaseWhat happens
pre_buildWork out the image address and sign Docker in to ECR. These are the same commands you typed in Mission 1.
buildBuild the image, with two tags: the commit and latest. The commit is also passed in as BUILD_ID, which the app shows in its footer.
post_buildPush both tags.

Commit and push it:

git add buildspec.yml git commit -m "Add buildspec" git push
2

Connect AWS to GitHub

AWS needs permission to read your repository and to be told when it changes. That permission is a connection. The teammate who owns the GitHub repository should do this step, signed in to GitHub in the same browser.

  1. Open Developer Tools → Settings → Connections and choose Create connection.
  2. Select GitHub. Connection name: [[TEAM]]-github. Choose Connect to GitHub.
  3. GitHub asks you to authorize the AWS Connector for GitHub. Approve it.
  4. Back on the AWS page, choose Install a new app. Pick your GitHub account, select Only select repositories, choose your team's repository, and install.
  5. Choose Connect. The connection's status should become Available.
If the status says Pending

A pending connection cannot be used. Select it and choose Update pending connection to finish the GitHub approval. Connections created by Terraform or the CLI always start as Pending.

Why "only select repositories"? Least privilege again. AWS needs to read one repository, so let it read one repository.

3

Create the pipeline (and the build project inside it)

  1. Open CodePipeline → Create pipeline.
  2. On Choose creation option select Build custom pipeline, then Next.
  3. Pipeline settings. Name: [[TEAM]]-pipeline. Keep New service role. Next.
  4. Source stage. Source provider: GitHub (via GitHub App). Choose your connection, your repository, and the branch main. Next.
  5. Build stage. Choose Other build providers, then AWS CodeBuild, then Create project. A second window opens. Fill it in like this:
    SettingValue
    Project name[[TEAM]]-build
    Environment imageManaged image, Amazon Linux, Standard runtime, the newest amazonlinux-x86_64-standard image
    Service roleNew service role, named [[TEAM]]-codebuild-role
    Additional configuration → PrivilegedTurn it on. Without it, docker build cannot run.
    Additional configuration → Environment variablesAWS_ACCOUNT_ID = your 12-digit account number
    IMAGE_REPO_NAME = [[TEAM]]-sleigh-list
    CONTAINER_NAME = sleigh-list
    BuildspecUse a buildspec file
    Choose Continue to CodePipeline. Back in the wizard, choose Next.
  6. Test stage: skip it. Deploy stage: skip it for now. Review, then Create pipeline.

The pipeline starts by itself. The Source stage should go green. The Build stage will probably go red. Good. Go and read why.

4

Read the build log and fix the permissions

In the failed Build stage choose View details or View logs. Scroll to the first error. It will be about ECR, and it will contain the words not authorized.

The build runs as [[TEAM]]-codebuild-role. The console gave that role enough rights to write logs and fetch the source, and nothing else. It may not sign in to ECR or push to it.

  1. Open IAM → Roles and find [[TEAM]]-codebuild-role.
  2. Choose Add permissions → Attach policies.
  3. Attach AmazonEC2ContainerRegistryPowerUser.
  4. Back in the pipeline choose Release change to run it again.

This time both stages go green, and a new image appears in your ECR repository with two tags: latest and a seven-character commit.

5

Prove it

  1. In your workshop, change BANNER in src/config.js.
  2. Commit and push.
  3. Watch the pipeline start within a few seconds, without anyone clicking anything.
  4. Check ECR for an image tagged with your new commit.

You have continuous integration: every commit becomes a tested, stored, traceable image. Next, make the pipeline deliver it: Deploy to Fargate.

YAML_FILE_ERROR or "buildspec.yml not found"The file is missing from the branch, is not at the top level, or has an indentation mistake. YAML uses spaces, never tabs.
not authorized to perform: ecr:...The CodeBuild role is missing the ECR policy (step 4).
