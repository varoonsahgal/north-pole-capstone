Designed for four teams of about four working at the same time in one AWS account, in us-west-2. Eight team names are built in: dasher, dancer, prancer, vixen, comet, cupid, donner, blitzen. Keep rudolph for your own demos.

Before class

  1. Assign teams and reindeer names. The team name becomes the prefix of every resource, so each team must have a different one.
  2. Check student access. Each student needs console access to the shared account with rights to create IAM roles, EC2, ECS, ECR, Lambda, API Gateway, CodeBuild, CodePipeline, EKS, CloudFront, Secrets Manager and CloudFormation. The course's existing AdministratorAccess setup is enough.
  3. Check the default VPC. Everything uses the default VPC and its public subnets in us-west-2. If the default VPC was deleted, recreate it with aws ec2 create-default-vpc.
  4. Check quotas (defaults are fine for four teams):
    QuotaUsed per team
    Elastic IPs1 (the workshop)
    CloudFront distributions1
    Application Load Balancers1, plus 1 classic load balancer from Kubernetes
    Fargate vCPUAbout 1.25
    EC2 vCPU2 (workshop) + 4 (two EKS nodes)
    VPCs0, provided teams use the eksctl command in the EKS guide
  5. Optional: launch the workshops yourself the day before, to save ten minutes of Mission 1. From CloudShell: for team in dasher dancer prancer vixen; do curl -fsSL https://varoonsahgal.github.io/north-pole-capstone/workshop/launch.sh | bash -s -- $team & done wait Each prints a URL and a password to hand to that team. The launch step in Mission 1 is safe to run again: it just prints the same details.
  6. GitHub accounts. For Mission 2, at least one person per team needs a personal GitHub account that can install the "AWS Connector for GitHub" app on one repository.

Running Mission 1

  • Timing was measured on a clean run: workshop launch 8 minutes, first image build under 1 minute, load balancer creation 2.5 minutes, the final rolling replacement 3 to 4 minutes, terraform destroy about 3 minutes.
  • The three failures in steps 7 and 8 are deliberate: the missing network configuration, the load balancer with no listener, and unhealthy targets caused by the default security group. Resist rescuing teams too early in step 8. Two minutes of discussion before the hints is where the learning happens.
  • If a team falls behind, the tested files for every step are in the site repository under solutions/capstone-1/.
  • End of session: teams run terraform destroy and keep the workshop.

Running Mission 2

  • Deliberate mistake. The gift API guide's Lambda returns a list as the body. The Lambda test passes, and API Gateway returns 502 "Malformed Lambda proxy response". The fix (json.dumps) is behind a "last resort" box at the end of that guide. CORS is the second lesson, when the app first calls the API.
  • EKS takes 15 minutes to create and 10 to delete. Tell teams to start it early in the second half. Make sure they use the eksctl command from the guide, which uses the default VPC. The stock command creates a VPC and a NAT gateway per cluster.
  • EKS console access. The cluster's only administrator is the workshop's IAM role. Students see "Error loading resources" in the console until they add an access entry for their own user. This is intended, and it prepares them for giving the build role access.
  • One pipeline run takes about 4 minutes for ECS, or about 5 with the Kubernetes step.
  • Reference solution. A complete, tested solution (Dockerfile, buildspec, Kubernetes manifests, Lambda and Terraform) is in the private repository varoonsahgal/sleigh-list-solution.

After the course

  1. Have each team follow the cleanup guide.
  2. Check each team for leftovers: for team in dasher dancer prancer vixen; do curl -fsSL https://varoonsahgal.github.io/north-pole-capstone/workshop/leftovers.sh | bash -s -- $team done
  3. Delete the workshops: for team in dasher dancer prancer vixen; do aws cloudformation delete-stack --stack-name $team-workshop --region us-west-2 done

How the workshop is built

The launch command downloads launch.sh, which deploys the CloudFormation template workshop.yaml. Per team it creates:

  • An EC2 instance (Amazon Linux 2023) with Docker, Terraform, kubectl, eksctl, helm and code-server installed at boot. Tool versions are pinned at the top of the instance's setup script in the template.
  • An IAM role with AdministratorAccess, matching what students already have, so Terraform and the CLI work without access keys.
  • A CloudFront distribution that provides HTTPS. The instance's security group accepts traffic only from CloudFront.
  • A random password in Secrets Manager (TEAM-workshop-password), and an Elastic IP so the address survives a stop and start.

Anyone with the URL and password has administrator access to the account through the workshop's terminal. Treat the pair as a credential, and delete the stacks when the course ends.

The site itself is built by build.py from src/pages into docs/, which GitHub Pages serves.
